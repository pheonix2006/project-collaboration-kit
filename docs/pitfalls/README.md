# 常见陷阱（Pitfalls）

本目录记录已经出现且可跨任务复用的故障规律、触发条件和规避方式，目标是防止同类错误
再次发生。

## 归类方式

- 按稳定的问题或错误领域组织文件，不按日期、会话、里程碑或负责人拆分。
- 同一根因或同一预防检查能够覆盖的问题放在同一主题文件中。
- 一个主题文件变得过大或出现不同维护边界时再拆分，不预先创建空分类。
- 本 README 负责维护“症状关键词 → 主题文件”的路由；出现第一个真实主题文件时再增加路由表。

可选领域示例包括文档与 Git、认证与凭据、运行环境与网络、数据与 Schema、部署与发布。
这些只是分类启发，不是固定目录要求。

## 条目结构

每条经验使用以下结构：

1. **症状**：可观察的错误现象与识别方式。
2. **原因**：经过证据验证的根因；尚未确认时明确写“未知”。
3. **规避**：执行前检查、失败策略或防复发措施。
4. **证据**：相关 dev-log、测试、提交或运行产物。
5. **适用边界**：适用的版本、环境、路径或前置条件。

## 与其他记录的边界

- 单次事故的完整时间线和处理过程属于 `../dev-log/`，不要复制到这里。
- 当前阻塞和下一步属于 `../current-development-status.md`。
- 已确认的设计取舍属于 `../specs/`，已经授权的执行步骤属于 `../plans/`。
- 只有跨任务仍有复用价值的错误规律才进入 pitfalls。
- 已经稳定成为强制边界的规避措施应提升到根 `AGENTS.md`、测试或自动检查；本目录保留原因、适用边界和证据。
