# 2026-07-22 - 标准项目骨架重构

## 背景

仓库最初以核心原则、信息权威、文档生命周期、跨会话工作流、定制指南和案例说明为主，
更像一套需要阅读和理解后再手工迁移的说明书。这个形态能够解释机制，但不能直接成为
其他项目的工作起点，也让仓库自身与它倡导的结构分离。

本里程碑把仓库改为可直接 fork 的标准项目骨架：仓库自身使用最终目录和生命周期，fork
后的使用者通过修改真实项目内容完成定制，不依赖模板同步、隐藏目录或额外工具。

## 改动

- 建立 `docs/specs/active/` 和 `docs/plans/active/`，保存本次已确认设计与当前可执行计划。
- 按设计建立 specs、plans、dev-log、pitfalls、decisions、reports 的生命周期目录。
- 新增 `docs/project-overview.md`，记录本仓库的使命、目标、非目标、使用者、结构、fork
  流程和长期质量标准。
- 新增 `docs/current-development-status.md`，把本次重构作为唯一当前状态，并明确已验证、
  进行中、阻塞、下一步和证据入口。
- 新增本月索引和本记录，使本次实施能从仓库内恢复，而不依赖原始会话。

## 验证

- 已逐项对照 active 设计和 active 计划，四份状态文档均描述本仓库当前重构事实，没有使用
  “项目名称”“待填写”等占位字段。
- 已检查四份文档之间的职责：overview 保存长期边界，current status 保存当前快照，本月
  README 负责索引，本记录保存里程碑证据。
- 实施中已对当时已跟踪的差异运行 `git diff --check`；全部新文件进入 index 后还必须执行
  最终检查，最终结果将在本记录收口时更新。
