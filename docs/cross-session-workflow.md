# 跨会话工作流

本页把[信息权威来源](source-of-truth.md)与[文档生命周期](document-lifecycle.md)转成可执行的会话协议。它规定先读什么、何时扩大范围、谁作决定，以及结束时把哪些事实写回哪里；不要求项目采用固定目录。

## 1. 会话启动：渐进读取

### 1.1 先给任务分类

开始前，用任务的主要目的确定读取深度：

| 任务类型 | 典型问题 | 首要读取目标 |
| --- | --- | --- |
| 定位或答疑 | “现在是什么状态？”“这个事实以哪里为准？” | 稳定规则与项目入口；必要时当前状态 |
| 小改动或验证 | 修复、补充测试、核对一个已有结论 | 稳定规则、相关代码/测试/配置，以及当前状态 |
| 设计或范围判断 | 选择方案、改变边界、解释关键取舍 | 稳定规则、项目总览、当前状态和相关当前设计 |
| 已授权执行 | 落实已确认的复杂工作 | 稳定规则、当前状态和对应的当前可执行计划 |
| 追证或复盘 | 核对过去为何判断、验证过什么 | 稳定规则、当前入口，以及索引定位到的相关里程碑证据或历史材料 |

任务可以同时属于多类；从最直接的一类开始，只在新的问题出现时增加材料。聊天记录只可提供线索，不能代替项目的权威入口或技术证据。

### 1.2 默认最短读取链

除非任务明确只要求查看一个已知文件，新会话按下面顺序读取：

1. 读取稳定规则与项目入口，了解阅读路由、约束和信息职责。
2. 任务需要判断当前工作时，读取唯一的当前状态入口。
3. 任务需要整体边界时，再读取项目总览。
4. 任务涉及架构或关键取舍时，只读取相关的**当前有效**设计；不要用草拟或已替代设计作依据。
5. 任务是已授权执行时，只读取对应的**当前可执行**计划，并核对它的范围、责任和验收条件。
6. 对实现、配置、测试与运行结果，读取可定位的技术事实；它们优先于描述性文档。

默认不整读全部开发日志、踩坑记录、设计、计划、报告或归档材料，也不因历史 TODO 存在而把它当作当前授权。

### 1.3 追证与扩大读取范围

需要过往证据时，先从项目入口、当前状态或里程碑索引按标题、日期、关键词、产物标识或链接定位，再读取一份最相关的记录。只有该记录不能回答问题时，才沿其链接扩大到相邻证据、替代材料或原始日志。

下列情况说明信息不足，应明确记录未知项并逐级扩大读取，而不是凭记忆补全：

- 当前入口没有说明任务范围、阻塞、验证结论或下一步；先读取项目总览或相应当前设计/计划。
- 文档结论与代码、测试、配置或运行产物冲突；先以可定位的技术证据核对，再更新摘要或状态。
- 当前材料引用的证据找不到、范围不明或口径不同；按索引进入相关里程碑或历史材料。
- 需要理解某项替代或归档决定；读取该材料所指向的新权威内容，并只追溯必要历史背景。

扩大读取的停止条件是：已能说明当前事实、依据、风险与下一步。若仍不能确认，写明“未知”和待核实项，不把历史文字升级为当前结论。

## 2. 会话执行：分工、决策与验证

### 2.1 主代理与子代理

主代理先明确目标、边界、非目标、可接受风险和完成标准，负责综合证据、作出方案取舍，并对最终写回负责。子代理适合承担可独立验证的探索、跨目录检索、重复性检查、日志整理或对照审阅。

子代理的输出应包含所查范围、证据位置、推断与未验证部分。主代理必须回读关键证据或重新运行关键验证，才能把结论写入当前状态、设计、计划或里程碑证据；子代理结论本身不是权威事实。

### 2.2 边界决策门

在执行中遇到下列变化时暂停并判断，而不是将其悄然扩大为原任务的一部分：

| 触发 | 决策门 | 允许继续的条件 |
| --- | --- | --- |
| 发现新需求、外部依赖或影响范围 | 是否仍在原目标和授权范围内？ | 范围不变，或已获得新的明确确认 |
| 需要改变长期边界或关键架构 | 是否已有可用的当前设计结论？ | 取舍、影响和责任已确认并写入当前设计或总览 |
| 需要执行多步、不可逆或高风险工作 | 是否存在当前可执行计划及验收？ | 范围、责任、验证和回滚/风险已确认 |
| 证据相互冲突或不足 | 技术事实和主要权威入口是否已核对？ | 冲突已消解，或未知项和待核实动作已显式记录 |

未通过决策门时，可以继续做只读调查或准备草拟材料，但不得把草拟、旧计划或聊天推断当作执行授权。

### 2.3 用层级报告验证

验证记录必须写明命令、证据位置、范围、结果和未覆盖风险，并标注实际达到的层级：

| 层级 | 说明 |
| --- | --- |
| 静态检查 | 格式、链接、类型、lint 或可读性检查；不证明运行行为。 |
| 单元测试 | 单个模块或规则在隔离条件下的行为。 |
| 集成验证 | 多个组件、接口或数据流共同工作。 |
| 真实运行 | 真实环境、凭据、服务或用户路径下的 smoke/端到端运行。 |
| 业务质量 | 输出是否满足任务质量、准确性或用户目标；与基础设施可运行分开报告。 |

不要以“跑通了”覆盖多个层级；例如集成验证成功不等于真实运行或业务质量已验证。

## 3. 结束：里程碑写回与交接

### 3.1 写回决策树

在任务结束或达到里程碑时，从事实类别而非文件习惯决定写回位置：

```text
本轮是否产生影响后续判断的新事实？
├─ 否 → 仅保留必要的任务交接；不要制造重复记录。
└─ 是
   ├─ 当前目标、阻塞、验证层级或统一下一步改变？ → 更新唯一当前状态入口
   ├─ 长期目标、边界或架构取舍改变？ → 更新项目总览或当前设计
   ├─ 已确认并允许执行的复杂后续工作？ → 建立或更新当前可执行计划
   ├─ 改动、验证、产物或缺口需要追溯？ → 写入相应里程碑证据
   └─ 已被稳定证据支持、可跨任务复用的规律？ → 更新可复用经验
```

一个事实只在其主要权威位置写全文；其他材料只保留必要摘要和链接。计划完成、设计被替代、报告口径变更或当前状态形成新版本时，同一里程碑还要：将旧材料标为已完成、已替代或历史材料，保留证据和替代链接，并更新入口/索引，使默认读取路径只指向仍有效内容。

### 3.2 最终交接检查清单

- 当前状态是否准确说明工作焦点、验证层级、阻塞、风险和统一下一步？
- 新增结论是否写到唯一主要权威位置，并有可定位的技术或里程碑证据？
- 已完成、已替代和历史材料是否已退出默认读取路径，且索引或替代链接同步更新？
- 是否避免复制同一事实全文、写入敏感信息，或把机器绝对路径当成通用规范？
- 下一会话能否仅依赖入口、当前状态和必要的按需材料恢复工作，而不依赖本次聊天？

### 3.3 端到端示例

新会话收到“完成当前已授权的接口改动并报告结果”。它先读稳定规则、项目入口和当前状态，发现状态链接到一份当前可执行计划；因此只读取该计划及相关代码和测试。子代理分别核对接口调用点和测试覆盖，主代理回读调用点并运行集成验证，确认改动虽通过集成验证但尚未进行真实运行。

该会话把改动、命令、集成验证和“真实运行未覆盖”的风险写入里程碑证据；将当前状态更新为新的验证层级和统一下一步。若计划的验收已完成，则把计划标为已完成、从当前计划入口移出，并由索引链接到里程碑证据。这样下一会话从入口和当前状态即可恢复，不会把已完成计划重新执行。
