# 项目总览

## 使命

本仓库维护一套可直接 fork、由 Git 管理、适合人与代理长期协作的标准项目骨架。它不把
跨会话协作停留在一组说明文档中，而是让仓库自身使用清晰的入口、唯一当前状态、显式的
设计与计划生命周期，以及可追溯的实施证据。

## 目标

- 新会话从根 `AGENTS.md` 出发，按任务渐进读取，而不是重新扫描全部历史。
- 让当前状态、当前设计、当前计划、历史证据、可复用经验和权威报告各有明确落点。
- 让目录位置直接表达 spec、plan 和 report 的生命周期，避免旧材料重新成为当前指令。
- 让每个里程碑的改动、验证、证据和剩余事项进入 Git 历史，可被后续会话恢复。
- 让使用者 fork 后只需修改仓库内真实内容，即可形成自己的项目协作基线。

## 非目标

- 不提供模板同步服务、初始化 CLI、隐藏管理目录或项目 Profile。
- 不要求所有项目启用所有文档类型，也不为结构完整而制造空内容。
- 不替代代码、测试、实际配置、运行产物或业务系统本身的技术权威性。
- 不集中保存下游项目状态，也不要求 fork 后持续跟随本仓库更新。

## 使用者

- 需要跨多次会话推进工作的项目维护者。
- 共同修改同一仓库的人类协作者。
- 需要低上下文恢复项目边界、当前任务和验证证据的编码或研究代理。
- 希望基于同一骨架建立项目特定规则的团队。

## 仓库结构

```text
AGENTS.md                       稳定协作规则和新会话入口
README.md                       面向人的项目入口与 fork 指南
docs/README.md                  文档路由和目录状态说明
docs/project-overview.md        本项目使命、边界和长期标准
docs/current-development-status.md
                                唯一项目级当前状态与下一步
docs/specs/active/              当前有效设计
docs/specs/archive/             已完成、被替代或退役的设计
docs/plans/active/              已确认且当前允许执行的计划
docs/plans/archive/             已完成、取消或被替代的计划
docs/dev-log/YYYY-MM/           按月份和里程碑保存的实施证据
docs/pitfalls/                  跨任务可复用的故障规律
docs/decisions/                 难以从代码或设计直接解释的既成决定
docs/reports/current/           当前权威报告
docs/reports/archive/           已被替代的历史报告
```

目录负责表达材料当前处于什么状态；索引负责说明如何读取，不再另建一层理论说明作为
运行前提。

## Fork 流程

具体操作以根 [README 的“Fork 后最短定制”](../README.md#fork-后最短定制)为准。
本文件只负责长期边界：fork 后的项目必须写入自己的真实使命和质量标准，清理与新项目
无关的历史材料，并独立演进；它不依赖本仓库的同步工具或隐藏状态。

## 长期质量标准

- **真实**：入口和状态描述当前仓库事实，不使用待填写模板冒充项目文档。
- **唯一**：每类事实有一个主要权威位置，其他位置只摘要并链接。
- **可恢复**：新会话能从短入口定位当前工作，并从里程碑记录追溯证据。
- **可验证**：完成声明写明静态检查、测试、集成或真实运行所达到的层级和证据。
- **可演进**：当前与归档材料物理分层，完成、取消或被替代时同步迁移。
- **低上下文**：默认读取链保持短小，历史材料先经过索引和关键词筛选。
- **安全**：正式文件不包含凭据、个人信息、机器相关绝对路径或不必要的大体量产物。
- **Git 完整**：里程碑以边界清楚的变更和记录进入版本控制，链接与工作树状态可检查。
