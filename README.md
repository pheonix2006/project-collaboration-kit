# 标准项目骨架

这是一个可直接 fork 的长期项目仓库骨架。它把协作规则、项目背景、当前状态、设计、计划和历史证据放在固定且有状态的入口中，让人和代理能在新会话中快速恢复正确上下文。

本仓库自身正在使用这套结构；fork 后不需要安装工具、同步上游模板或引入隐藏管理目录。

## 实际结构

```text
AGENTS.md                         稳定协作规则与项目地图
README.md                         面向人的项目入口
docs/
  README.md                       文档路由与目录状态
  project-overview.md             项目使命、边界与长期质量标准
  current-development-status.md   唯一的当前状态与下一步
  specs/active/                   当前有效设计
  specs/archive/                  已完成或被替代的设计
  plans/active/                   已确认、当前允许执行的计划
  plans/archive/                  已完成、取消或被替代的计划
  dev-log/YYYY-MM/                按月保存的实施与验证证据
  pitfalls/                       可复用的故障规律
  decisions/                      重大既成决定及其依据
  reports/current/                当前权威报告
  reports/archive/                已被替代的报告
```

目录位置本身表达材料状态：`active` 和 `current` 是当前入口，`archive` 与开发日志只用于追溯，不能自动恢复为待执行指令。

## Fork 后最短定制

1. 在本文件改写项目名称、定位和常用使用方式。
2. 在 `docs/project-overview.md` 写清使命、目标、非目标和真实项目结构。
3. 在 `docs/current-development-status.md` 写入当前进展、阻塞和统一下一步。
4. 在 `AGENTS.md` 更新项目地图、验证命令和项目特定边界。
5. 删除或归档与新项目无关的历史设计、计划和开发日志。

其余目录只在产生真实材料时使用；不要为了填满骨架而创建空泛文档。

## 日常使用

- 开始任务：先读 `AGENTS.md`，再按其中的渐进读取顺序加载必要上下文。
- 讨论并确认方案：将仍有效的设计写入 `docs/specs/active/`；仅当计划已获授权执行时，写入 `docs/plans/active/`。
- 执行与验证：把过程、命令、结果和证据位置记入当月 `docs/dev-log/YYYY-MM/`，并明确验证层级。
- 遇到可重复的问题：按错误所属领域更新 `docs/pitfalls/`，沉淀复现条件、根因和预防方式。
- 更新当前面貌：将项目级进展、阻塞和下一步收敛到 `docs/current-development-status.md`。
- 结束或替代材料：移动到相应 `archive/`，并更新索引或当前状态，避免历史材料继续充当指令。

文档的具体路由和写入位置以 `AGENTS.md` 与 `docs/README.md` 为准。

## Pitfalls 如何归类

`docs/pitfalls/` 用来防止已经确认的错误模式再次发生。它按稳定的问题领域归类，不按日期、
会话或单次任务归档。例如可以按文档与 Git、认证与凭据、运行环境与网络、数据与 Schema、
部署与发布等领域分别成文；具体分类应跟随项目真实错误边界，不必照搬这些名称。

每个条目至少说明：

- **症状**：出现什么现象，如何识别。
- **原因**：已经验证的根因；无法验证时明确标记未知。
- **规避**：以后执行前应检查什么，怎样防止再次发生。
- **证据**：对应日志、测试、提交或运行产物的位置。
- **适用边界**：哪些环境或条件适用，避免把局部经验误写成全局规则。

单次事故的时间线和处理过程写入 `dev-log/`；只有能够跨任务复用的错误规律才进入
`pitfalls/`。如果某条规避措施已经稳定成为强制边界，应进一步提升到 `AGENTS.md`、测试或
自动检查中，pitfall 继续保留“为什么需要这条规则”和证据。详细维护方式见
[`docs/pitfalls/README.md`](docs/pitfalls/README.md)。

## 非目标

这个骨架不提供 CLI、初始化脚本、自动同步、集中式状态服务或固定的业务架构；也不替代代码、测试、部署配置和运行产物本身的技术权威性。它只提供一套轻量、可演进的仓库协作结构。
